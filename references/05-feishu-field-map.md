## 1. 建表结构

每张表 = 一个月的记录（或一个会话的所有记录，视规模而定）。

| 字段名 | 类型 | 来源列 | 说明 |
|---|---|---|---|
| 发送时间 | 日期 | `ts` | 毫秒时间戳写入，显示到分钟 |
| 日期 | 日期 | `ts` | 只显示日期，用于分组 |
| 发送者 | 文本 | `sender_name` | 群昵称 |
| 消息类型 | 单选 | `type` | 10 个固定选项 |
| 内容 | 多行文本 | `content` | 主文本 |
| 引用内容 | 多行文本 | `quote_content` | 有则填 |
| 附件 | 附件 | `media_path` | 图片直接挂这里 |
| 附件链接 | 超链接 | `media_path` | 大文件走这里 |
| 是否本人 | 复选框 | `is_self` | 1 → true |
| 消息ID | 文本 | `msg_id` | **幂等键，建议隐藏** |
| 原始类型 | 数字 | `raw_type` | 排错用，建议隐藏 |

> 隐藏字段不影响写入和筛选，只是界面上收起来。幂等键建议隐藏，免得看表时被一串 hash 干扰。

## 2. 字段类型对照

飞书多维表格字段 `type` 枚举（创建字段时用）：

| type | 含义 | 本技能用到 |
|---|---|---|
| `1` | 多行文本 | ✅ 内容、引用内容、消息ID |
| `2` | 数字 | ✅ 原始类型 |
| `3` | 单选 | ✅ 消息类型 |
| `4` | 多选 | ⬜ |
| `5` | 日期 | ✅ 发送时间、日期 |
| `7` | 复选框 | ✅ 是否本人 |
| `15` | 超链接 | ✅ 附件链接 |
| `17` | 附件 | ✅ 附件 |
| `1001` | 创建时间 | ⬜ 系统自动 |
| `1005` | 自动编号 | ⬜ |

## 3. CellValue 构造

### 3.1 文本字段

两种写法都行：

```json
{ "内容": "这是一条消息" }
```

```json
{ "内容": [{ "type": "text", "text": "这是一条消息" }] }
```

**推荐第二种**，因为可以带链接和样式。纯文本用第一种更快。

⚠️ 多行文本里的换行直接写 `\n`，不要转义成字面量 `\\n`。

### 3.2 日期字段

**必须是毫秒时间戳**（13 位）。秒级时间戳会被当成 1970 年。

```json
{ "发送时间": 1758336000000 }
```

CSV 里的 `ts` 是秒级，写入前 × 1000：

```python
ts_ms = int(row["ts"]) * 1000
```

如果工具给的是字符串日期，先转：

```python
from datetime import datetime
ts_ms = int(datetime.strptime(row["datetime"], "%Y-%m-%d %H:%M:%S").timestamp() * 1000)
```

### 3.3 单选字段

写**选项名**，不是选项 ID：

```json
{ "消息类型": "text" }
```

选项不存在时飞书可能自动新增（取决于配置）。**建表时先把 10 个选项全部建好**，避免自动新增造出脏选项。

### 3.4 复选框

```json
{ "是否本人": true }
```

CSV 里的 `1` / `0` 要转 bool，直接传字符串 `"1"` 会被拒。

### 3.5 超链接

```json
{ "附件链接": { "link": "https://...", "text": "查看文件" } }
```

或直接传 URL 字符串。

### 3.6 数字字段

```json
{ "原始类型": 49 }
```

传字符串 `"49"` 可能报类型不匹配，务必转 int。

## 4. 附件字段

### 4.1 上传流程

```
本地文件
  ↓ POST /open-apis/drive/v1/medias/upload_all
     parent_type=bitable_image   （图片）
     parent_type=bitable_file    （其他文件）
  ↓ 返回 file_token
写入记录：{ "附件": [{ "file_token": "boxcnxxxx" }] }
```

### 4.2 `parent_type` 怎么选

| 文件类型 | parent_type |
|---|---|
| jpg / png / gif / webp / bmp | `bitable_image` |
| pdf / docx / xlsx / zip / mp4 … | `bitable_file` |

选错会导致附件在表里显示不出来（但接口可能返回成功，很坑）。

### 4.3 混合策略（本技能默认）

| 类型 | 大小 | 去向 |
|---|---|---|
| 图片 | ≤ 20 MB | 附件字段 |
| 图片 | > 20 MB | 云盘 + 链接 |
| 视频 / 文档 / 压缩包 | 任意 | 云盘 + 链接 |
| 表情、缩略图 | 任意 | 跳过 |

### 4.4 附件字段的限制

- 单条记录附件数量有上限（通常 50 个），超了要拆分
- 单 Base 附件总量有配额，17,000 个文件要留意
- 同一个 `file_token` 可以复用到多条记录，**附件按 md5 去重后再上传**，能省一大半时间

## 5. 字段创建 JSON

创建表：

```
POST /open-apis/bitable/v1/apps/{app_token}/tables
{
  "table": {
    "name": "微信记录_2026-08",
    "default_view_name": "全部消息",
    "fields": [ ...见下... ]
  }
}
```

字段示例：

```json
[
  { "field_name": "发送时间", "type": 5,
    "property": { "date_formatter": "yyyy/MM/dd HH:mm", "auto_fill": false } },
  { "field_name": "日期", "type": 5,
    "property": { "date_formatter": "yyyy/MM/dd", "auto_fill": false } },
  { "field_name": "发送者", "type": 1 },
  { "field_name": "消息类型", "type": 3,
    "property": { "options": [
      { "name": "text" }, { "name": "image" }, { "name": "voice" },
      { "name": "video" }, { "name": "file" }, { "name": "link" },
      { "name": "quote" }, { "name": "emoji" }, { "name": "system" },
      { "name": "other" }
    ] } },
  { "field_name": "内容", "type": 1 },
  { "field_name": "引用内容", "type": 1 },
  { "field_name": "附件", "type": 17 },
  { "field_name": "附件链接", "type": 15 },
  { "field_name": "是否本人", "type": 7 },
  { "field_name": "消息ID", "type": 1 },
  { "field_name": "原始类型", "type": 2 }
]
```

完整可导入版本见 `assets/bitable-template.json`。

## 6. 视图与仪表盘

表建好后，至少配三个视图，否则这张表等于一个巨大的 Excel：

| 视图 | 类型 | 配置 |
|---|---|---|
| **按天看** | 表格（分组） | 按「日期」分组，按「发送时间」升序 |
| **只看文件** | 表格（筛选） | 消息类型 ∈ {file, image, video} |
| **只看我自己** | 表格（筛选） | 是否本人 = true |
| **发言排行** | 仪表盘 | 按「发送者」计数，柱状图 |
| **时段分布** | 仪表盘 | 按「发送时间」小时聚合 |

> 视图配置通过 `+view-*` 命令或 OpenAPI 完成；如果使用豆包内置的 `lark-base` 技能，可以直接调它。

## 7. 分表策略

飞书单个数据表有记录数上限，做批量导入必须提前规划。

| 消息量 | 策略 | 表名 |
|---|---|---|
| ≤ 10,000 | 单表 | `微信记录` |
| 10,000 ~ 50,000 | 按月分表 | `微信记录_2026-08` |
| > 50,000 | 按月 + 按群分表 | `微信记录_<群>_2026-08` |

**分表时的边界规则**（最容易出错的地方）：

```
某条消息的时间戳 T
月份 = 按【本地时区】的 YYYY-MM 计算
不要用 UTC，否则每月最后一天的晚上会跑到下个月
```

跨表去重靠 `msg_id` 全局唯一，不是表内唯一。写入前按 `msg_id` 查一次目标表，已存在就跳过。

## 8. 一个反面案例

有人把 `raw_type` 建成单选，结果飞书自动新增了 30 多个选项，表头一团乱。

**教训**：只有取值固定的字段才用单选。`raw_type` 理论有上百种值，必须是**数字**。
