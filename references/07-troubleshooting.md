## 1. 取数阶段

### 找不到数据目录

| 可能原因 | 验证 | 处理 |
|---|---|---|
| 文档目录被重定向到别的盘 | 全盘搜 `xwechat_files` | 用探测脚本的扫描结果 |
| 从未登录过微信 | 目录不存在 | 让用户先登录一次 |
| 用的是「微信」不是「Weixin」 | 看注册表 `Tencent\WeChat` vs `Tencent\Weixin` | 分别是 3.x / 4.x |
| 权限不足 | 以普通用户能否访问 | 不要在无权限时强行提权 |

### 工具读不出数据

| 症状 | 原因 | 处理 |
|---|---|---|
| 提示「未配置」 | WeFlow 需要第三方解密组件 | 换工具，或配组件 |
| 启动报 `-101` / `WCDB 初始化失败` | 内置 `wcdb_api.dll` 带构建过期开关，到期自毁 | 见下方「工具自毁」 |
| 打开就闪退 | 微信版本太新，工具没适配 | 换工具；**不要降级微信客户端**（风险高） |
| 显示 0 条消息 | 库路径指错 / 密钥错 | 确认路径；换工具 |
| 只有最近几条 | 只读了 WAL，没读主库 | 工具没正确处理 `.db-wal` |
| 中文全是乱码 | 编码不是 UTF-8 | 导出时选 UTF-8 |
| 导出的发送者全是「未知发送者」 | `Name2Id` 映射缺失 | 看 JSON 的 `sender_status`，确认是哪种原因 |

### 工具自毁：WeFlow 的 `-101`

WeFlow 5.0.0 随包的 `resources/resources/wcdb/win32/x64/wcdb_api.dll` 内部硬编码了两个过期时间戳，都指向 **2026-09-30 23:59:59**。到期后：

```text
InitProtection() → -101
wcdb_init()      → -1000
现象：启动弹窗「WeFlow 启动失败 / 错误码: -101」
```

**这不是用户环境问题，也不是安装损坏。** 重新安装、修复安装、`npm run build` 全都无效——重建只是把同一个过期 DLL 再打一次包。

处理：

1. 换工具（推荐，成本最低）
2. 用社区补丁修补 DLL（`AnonymousUser443/WeFlow-Community-Patch`），注意重装/升级后会失效，需要重打

> 遇到这种「软件自己到期」的情况，先看仓库 issue 和社区补丁，不要浪费时间去排查自己的环境。

### 版本适配失败

这是最没辙的情况。处理顺序：

1. 查工具的最新 release 说明（可能刚支持）
2. 换一个工具
3. 找旧版工具（风险自负）
4. **放弃自动化，改手工**：微信客户端内「聊天记录迁移」到另一台设备，在那边用旧版微信

> 不要为了适配工具去降级微信客户端。降级过程不稳定，还可能丢数据。

## 2. 数据质量

### 发送者全是 wxid

`wxid` 没被翻译成昵称。原因：导出时没勾「解析昵称」，或工具没读联系人库。

处理：
- 重新导出并开启昵称解析
- 或从 `contact.db` / `MicroMsg.db` 单独导出成员表，做一次 join

**不要**接受「全是 wxid」的结果——飞书表里看到一片 `wxid_azigx...`，等于没用。

### 时间是 1970 年

时间戳单位错了。常见三种：

| 源值 | 实际单位 | 写入飞书 |
|---|---|---|
| `1758336000` | 秒 | × 1000 |
| `1758336000000` | 毫秒 | 直接用 |
| `"2026-08-01 09:12:33"` | 字符串 | 先 parse 再转毫秒 |

### 时间整体差 8 小时

UTC 和本地时区混了。所有时间统一按 **UTC+8** 处理，分表时的月份边界也按 UTC+8 算。

### 引用关系全部丢失

`quote_msg_id` 拿不到。原因：工具没解析 `49` 类的 `<refermsg>`。

处理：至少保留 `quote_content`（被引用的文字），比空着强。要完整关系，换工具重导。

### 类型全是 other

工具没做类型映射，`localType` 直接透传了。看 `raw_type` 分布，手工补映射表（`03-data-contract.md` §3）。

### 系统消息混进正文

入群提示、撤回提示混在聊天里。`type=system` 要打准，飞书侧用视图过滤掉。

## 3. 附件问题

### 图片是 .dat，打不开

微信把图片存成了自定义加密格式（不是标准图片）。

**正确做法**：用工具的「解密媒体 / 导出图片」功能，一次性全解出来。

**不要自己写解密器**：`.dat` 的密钥派生依赖 uin / 设备信息，格式还因版本而异，自己写大概率解出一堆花屏。工具已经有成熟实现，用现成的。

如果工具不支持解密，退而求其次：导出的 JSON 里通常带原图的 CDN 地址（`cdnthumburl` / `cdnbigimgurl`），但这些地址有时效，过期就废了。

### 语音点不开

语音是 **SILK** 编码，飞书不支持。

选项：

| 方案 | 效果 | 成本 |
|---|---|---|
| 不处理 | 表里只有 `[语音]` | 0 |
| 转 MP3 | 可播放 | 需要 silk-v3 转码器 + ffmpeg |
| 转文字 | 可读可搜 | 需要 ASR，量大成本高 |

建议：**一期不处理语音**，先把文本和图片跑通。语音单独评估。

### 附件缺失

`manifest.json` 里 `missing > 0`。常见原因：

- 消息太老，本地缓存已被清理
- 只导出了「缩略图」，原图不在
- 路径大小写/分隔符不匹配

对缺失的附件，保留记录但附件字段留空，在 `manifest.json` 里列清单。**不要伪造占位图**。

### 附件上传到一半失败

见 `06-feishu-api.md` §4.2。核心：按 md5 缓存 `file_token`，重跑时跳过已上传的。

## 4. 飞书写入

### 91403 Forbidden

99% 是没加文档协作者。见 `04-feishu-app-setup.md` §4。

### 1254015 字段值类型不匹配

| 字段类型 | 常见错误 |
|---|---|
| 日期 | 传了秒级时间戳或字符串 |
| 数字 | 传了字符串 `"49"` |
| 复选框 | 传了 `"1"` 而不是 `true` |
| 单选 | 传了选项 ID 而不是选项名 |

### 1254045 字段不存在

字段名拼错，或者有多余空格。先 `field-list` 拿真实名字，**不要凭 CSV 表头猜**。

### 记录写进去了但显示空白

大概率是字段类型错但被容错处理了。逐字段核对 `05-feishu-field-map.md` §3。

### 重复记录一堆

幂等没生效。检查：

- `msg_id` 是否稳定（同一源跑两遍是否一致）
- 写入前是否真的做了判重
- 是否并发写了同一批

## 5. 性能与耗时

### 到底要跑多久

先估再跑，别盯着进度条怀疑人生：

```
写记录：批数 × (请求耗时 + 间隔)
       5 万条 ≈ 250 批 × 0.5s ≈ 2 分钟
传附件：文件数 × (上传耗时 + 间隔)
       1.7 万文件 ≈ 17000 × 0.4s ≈ 2 小时
```

附件是绝对大头，别指望它快。

### 跑到一半越来越慢

可能撞限流了。看日志里 `1254290` 出现频率，加大间隔。

### 内存吃满

一次性把全部记录读进内存了。3 万条通常没问题；10 万以上要改成流式分批读 CSV。

## 6. 合规与安全

### 群里有别人的隐私

群聊是**多人的共同内容**，每个成员都是数据主体。

导入企业平台前应该：

- 在群里说明用途（存档、检索、复盘）
- 只导业务相关信息，不做整库搬家
- 飞书侧权限设最小可见范围

这不是流程洁癖，是《个人信息保护法》的硬要求。

### 密钥泄漏检查

交付前跑一遍：

```bash
# 排除占位符（连续 8 个以上相同字符，如 xxxxxxxx）
grep -rnE "cli_[a-z0-9]{16,}|app_secret\s*[:=]\s*[\"']?[A-Za-z0-9]{20,}" . \
  | grep -vE "cli_x{8,}|_x{8,}|x{20,}"
```

只应该命中文档里的占位符，命中真实值就删掉重来。

> 占位符（`cli_xxxxxxxx`）一定会被第一个正则命中，所以必须加第二道排除。别因为「扫出来一堆」就忽略这条检查。

### 不要提交的数据

`.gitignore` 至少包含：

```
.env
*.env
inbox/
clean/
*.db
*.csv
```

聊天记录和附件绝不能进代码仓库。
